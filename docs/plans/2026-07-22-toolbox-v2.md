### P0.2 + P0.3 Playback-kontroller + WS-omskrivning (EN design, sol-majors)

`demo_replay.py` skrivs om kring en **ensam playback-koordinator**:

- Koordinatorn äger playhead-index, klock-offset och state
  `playing|paused|stopped|finished`. Paus ackumulerar offset — inget
  tidshopp vid play. `stop` ⇒ playhead 0, tomma used/missing, `attempt_id`++,
  state `stopped` (frame 0 broadcastas fryst). `play` från
  `stopped|finished` ⇒ start från början. No-loop EOF ⇒ `finished` (sista
  framen hålls; play ⇒ omstart). Loop-läge: loopar endast i `playing`.
- **En writer-task per klient** med begränsad latest-frame-kö (maxlen 1,
  äldre snapshot kastas); ALLA utgående frames/pongs går via writer-tasken.
  Klientläsare parsar inkommande textframes → köar kommandon till
  koordinatorn (sekventiellt i mottagningsordning). Trasiga/okända/för stora
  (>1 KB) meddelanden ignoreras med loggrad. Disconnect/långsam klient får
  aldrig blockera övriga eller nya handshakes (= fixen för den BEKRÄFTADE
  wedge-buggen; rotorsaken beskrivs i findings-log).
- **Frame-fältet `"playback": {"state": ..., "t": ...}`** läggs till.
  Viewern parsar det som `Option<PlaybackState>` (serde default) —
  **knapparna visas ENDAST när fältet finns** (live-bryggan skickar det inte
  och ignorerar cmd-frames tyst). Gamla producenter fortsätter fungera.
- Viewer-WS-transporten görs till delat objekt (bort med `mem::forget`) med
  synlig disconnected-state; automatisk återanslutning är MINOR (ej krav).

Verifiering (ägarfritt, automatiserat): asyncio-test som kör play/pause/stop-
sekvenser och asserterar playhead/state/klockbeteende; churn-test (5 anslut+
dö mitt i stream, 1 långsam klient som aldrig läser) ⇒ färsk klient får frames
inom 1 s; gammal-producent-test (frame utan playback-fält parsas, knapplogik
av); manuell browser-E2E med skärmdumpar som slutbevis.

## P1 — Fysikorakel `bsp-probe` (rev 3 per sols hull-korrigering)

- **Grundmodell (sol-blocker):** proben tar spelar-ORIGIN som input och kör
  ett kort hull-1-spår NEDÅT från origin (ingen egen −24-offset; hullens
  extents ÄR spelarboxen). `grounded` ⇔ `!start_solid` ∧ träff inom 2,0u ∧
  `plane_normal.z >= 0.7`. Svar: `{"grounded", "floor_z"
  (= trace.endpos.z − 24, fysisk golvhöjd), "normal_z", "contents"
  (samplat vid origin), "status": "ok|solid|unknown|error"}`.
- **Static-world-orakel:** movers (dörrar/plattor/hissar) modelleras inte —
  punkter vars spår träffar mover-utrymme ger `unknown` (dokumenterat);
  konsumenten faller för sådana punkter tillbaka på heuristiken per punkt
  och FLAGGAR det i output. Ett probe-processfel mitt i en körning ⇒ hela
  körningen misslyckas eller görs om som ren heuristikkörning — aldrig tyst
  blandning.
- **Protokoll:** JSONL stdin/stdout, `{"v":1}`-versionsrad först, en request
  → en response, diagnostik på stderr, timeout i Python-sidan (5 s/anrop),
  crash ⇒ strukturerat fallbackskäl. Binär-discovery: explicit sökväg i
  qw-fasttrack-konfig (README), ingen PATH-magi.
- **API-wiring (sol-blocker):** `grounded_mask(samples, oracle=None)`;
  `ingest(...)` bygger oraklet från sin `map`-parameter;
  `demo_replay` CLI får `--map` (krävs för orakelväg; utan → heuristik +
  varningsrad). `missing_spec` ärver via ingest.
- **Pinad fixture (sol-major):** dm3.bsp sha256 pinnas i testfilen; exakta
  acceptanspunkter ur apex-specen §8.4: de fyra äkta punkterna
  `(-292.6,548.2,120)/(310.1,670.4,56)/(336.2,666.1,56)/(83.3,670.0,40)` ⇒
  grounded med floor_z ≈ z−24 ±1; apex-klasspunkt `(313,586,99.8)`-typ ⇒ ej
  grounded. Rust-testerna körs mot samma pinnade BSP (obligatoriska, inte
  skippbara). Komplett körkommando dokumenteras.
- Output/evidens bär: bsp-sha, probe-commit, metod `oracle|heuristic`.
- Prestanda: xersng-ingest < 30 s end-to-end (pinnacle, nice -19).
